# Критические точки

В предыдущих разделах мы рассматривали диапазоны / отрезки на числовой прямой с двумя важными ограничениями:

- все границы / координаты лежали в полуинтервале $[0; M)$;
- сложность по времени / памяти $O(M)$ считалась допустимой.

Но что делать, если эти ограничения не выполняются?

На самом деле нас интересует конкретно ограничение на допустимость сложности $O(M)$, потому что даже реальные задачи будут обладать каким-то заранее известным диапазоном координат $[M^-, M^+]$.

## Уход от обработки всех точек

В общем случае даны $N$ отрезков $[L_i, R_i]$ на числовой прямой, с $i$-м отрезком сопоставлено изменение $d_i$.

Для их обработки:

- в первую очередь мы изменяем значения разностного массива в точках $L_i$ (на $d_i$) и $R_i + 1$ (на $-d_i$) для каждого отрезка;
- затем мы анализируем каждую точку на числовой прямой в порядке возрастания координат, накапливая префикс-сумму обозначенных величин.

В более общем случае информация необязательно будет суммой - мы можем накапливать ответ в какой-то структуре данных.

Без потери общности будем считать, что

- в точке $L_i$ происходит операция $add(d_i)$;
- в точке $R_i + 1$ происходит операция $remove(d_i)$.

### Событийная модель

Обратите внимание - хотя на числовой прямой у нас есть $O(M)$ точек - какие-либо **изменения** нашего состояния происходят только в **конечных** точках отрезков $L_i$ и $R_i + 1$.

Назовём такие точки **критическими**, а сами изменения состояния - **событиями**.

Давайте конкретизируем, что мы знаем про критические точки:

- Всего критических точек не более $2N$ (по две на каждый отрезок), то есть $O(N)$ вместо $O(M)$.
- Между критическими точками состояние **не меняется**.

#### Интервалы стабильности

По сути критические точки разбивают числовую прямую на несколько **интервалов стабильности** - отрезков, на которых состояние не меняется.

Если обозначить критические точки через $c_0 < c_1 < c_2 < \ldots < c_k < c_{k + 1}$, то интервалы стабильности будут выглядеть так:

- $(c_0, c_1)$ со значением $V_0$, где $c_0 = M^-$;
- $[c_1, c_2)$ со значением $V_1$;
- $\ldots$
- $[c_{k-1}, c_k)$ со значением $V_{k-1}$;
- $[c_k, c_{k + 1})$ со значением $V_k$, где $c_{k + 1} = M^+$.

Чаще всего ответ на задачу строится из значений $V_i$:

- либо это сумма, в таком случае она равна $\sum_{i=0}^{k} V_i \cdot (c_{i + 1} - c_i)$;
- либо это экстремум (минимум / максимум), в таком случае он равен $opt(V_0, V_1, \ldots, V_k)$;
- либо ещё какое-то агрегированное значение.

Обратите внимание, что $V_i$ - это необязательно числовое значение, это может быть любое значение / свойство состояния, полученного накоплением уже обработанных событий.

### Сортировка событий

Простейший вариант обработки критических точек - честно отсортировать все события и обработать их в порядке возрастания координат.

- Сами события мы знаем из входных данных - это $add(L_i, d_i)$ и $remove(R_i + 1, d_i)$ для каждого отрезка.
- Сортировка всех событий занимает $O(N \log N)$ времени.
- Обработка всех событий занимает $O(N \cdot Op^+ + N \cdot Op^-)$ времени, где $O(Op^+)$ и $O(Op^-)$ - сложность операций $add$ и $remove$ соответственно.

#### События с одинаковой координатой

Обратите внимание, что в случае, если несколько событий имеют одинаковую координату, порядок их обработки может быть важен.

Общего правила здесь нет - всё зависит от конкретной задачи.

В первую очередь это зависит от строгости границ исходных отрезков:

- если отрезки заданы как $[L, R]$ (включительно), то событие $remove$ должно обрабатываться **после** события $add$ в той же точке;
- если отрезки заданы как $[L, R)$ или $(L; R]$ (полуинтервально), то событие $remove$ должно обрабатываться **до** события $add$ в той же точке.

#### Офлайн-запросы в точке

В некоторых задачах события могут быть не только изменениями состояния, но и запросами.

В этом случае обычно вводится отдельный тип события, который чаще всего ставится между событиями $add$ и $remove$.

Общая асимптотика в таком случае получается:

- $O((N + Q) \log (N + Q))$ на сортировку всех событий;
- $O(N \cdot (Op^+ + Op^-) + Q \cdot Op^?)$ на обработку всех событий, где $O(Op^?)$ - сложность обработки запроса.

Обратите внимание, что в таком случае запросы обрабатываются в режиме **офлайн** - все запросы известны заранее, а порядок их обработки может отличаться от порядка во входных данных.

#### Офлайн-запросы обратимых операций в интервале

Как известно, вычисление обратимых операций в интервале $(L; R]$ состоит из трёх этапов:

- вычисление значения в точке $L$ - $V_L$ за $O(Op^?)$ времени;
- вычисление значения в точке $R$ - $V_R$ за $O(Op^?)$ времени;
- объединение значений $V_L$ и $V_R$ за $O(Op^{*})$ времени.

Если сложность объединения $O(Op^{*})$ достаточно мала для конкретной задачи, то такое вычисление сводится

- к вычислению двух запросов в точках;
- объединению результатов в самом конце.

Суммарная сложность получается равной $O((N + Q) \log (N + Q) + N \cdot (Op^+ + Op^-) + Q \cdot (Op^? + Op^{*}))$.

#### Пример реализации

```cpp
auto get_ans = [&]() {
    using event_t = std::tuple<int, int, delta_t>; // {координата, тип события, изменение}
    std::vector<event_t> events = {
        { M_plus, op_remove, end_delta } // фиктивное событие в конце
    };

    // Собираем события из отрезков
    for (const auto& [left, right, delta] : segments) {
        events.emplace_back(left, op_add, delta); // событие "начала отрезка"
        events.emplace_back(right + 1, op_remove, delta); // событие "конца отрезка"
    }
    
    // Собираем события из запросов
    for (size_t index = 0; index < queries.size(); ++index) {
        const auto& [coord, _] = queries[index];
        events.emplace_back(coord, op_query, index); // событие "запроса"
    }

    // Сортируем события по координате
    std::sort(events.begin(), events.end());
    
    std::vector<ans_t> answers(queries.size()); // массив ответов на запросы

    state_t state = start_state; // объект состояния
    int last_coord = M_minus; // начальная координата

    for (const auto& [coord, op_type, event_data] : events) {
        // Обрабатываем интервал стабильности [last_coord, coord)
        process_stable_interval(last_coord, coord, state);

        // Обновляем состояние в зависимости от типа события
        if (op_type == op_add) {
            state.add(event_data);
        } else if (op_type == op_remove) {
            state.remove(event_data);
        } else if (op_type == op_query) {
            const auto& [_, query_type] = queries[event_data];
            answers[event_data] = state.ask(query_type);
        }

        last_coord = coord;
    }

    // возвращаем ответы на запросы
    return answers;
    
    // либо вычисляем один ответ из state
    // return compute_final_answer(state);
}
```

## Применение в задачах

### Объединение отрезков

#### Задача

Даны $N$ отрезков $[L_i, R_i]$ на числовой прямой.

Найдите объединение всех отрезков и выведите его в виде минимального количества непересекающихся отрезков.

#### Решение

- Новый отрезок из объединения начинается в каждой точке, где количество покрывающих отрезков меняется с $0$ на $>0$.
- Аналогично отрезок из объединения заканчивается в каждой точке, где количество покрывающих отрезков меняется с $>0$ на $0$.
- Будем поддерживать текущее количество покрывающих отрезков, обрабатывая критические точки в порядке возрастания координат.

#### Реализация

```cpp
auto get_ans = [&]() {
    const int op_add = 0, op_remove = 1; // 

    using event_t = std::tuple<int, int>; // {координата, тип события}
    std::vector<event_t> events;

    // Собираем события из отрезков
    for (const auto& [left, right] : segments) {
        events.emplace_back(left, op_add); // событие "начала отрезка"
        events.emplace_back(right, op_remove); // событие "конца отрезка"
    }

    // Сортируем события по координате
    std::sort(events.begin(), events.end());

    std::vector<segment_t> union_segments; // результат - объединение отрезков
    
    int cover_count = 0; // текущее количество покрывающих отрезков
    segment_t current_segment; // текущий отрезок объединения

    for (const auto& [coord, op_type] : events) {
        if (op_type == op_add) {
            // Начало нового отрезка
            if (cover_count == 0) {
                current_segment = segment_t{};
                current_segment.start = coord;
            }
            cover_count += 1;
        } else if (op_type == op_remove) {
            cover_count -= 1;
            // Конец текущего отрезка
            if (cover_count == 0) {
                current_segment.end = coord;
                union_segments.push_back(current_segment);
            }
        }
    }

    return union_segments;
}
```

### (Офлайн) Сумма в интервале без массива префиксных сумм

#### Задача

Массив $A$ размером $N$ задан рекуррентной формулой:

- $A_0 = 0$;
- $A_i = F(i, A_{i - 1})$ для $1 \le i \le N$.

Даны $Q$ запросов - вычислить сумму элементов массива в диапазоне $(L_j, R_j]$.

Ограничения по сложности:

- $O(N + Q \log Q)$ по времени;
- $O(Q)$ по памяти, но не $O(N + Q)$.

#### Решение

- Разобьём запросы в диапазоне на два запроса префиксной суммы в точках:
  - $S^-(L) = \sum_{i=0}^{L} A_i$;
  - $S^+(R) = \sum_{i=0}^{R} A_i$.
- Тогда сумма в диапазоне $(L, R]$ равна $S^+(R) - S^-(L)$.
- Можно рассмотреть два подхода вычисления: 
  - ориентированный на запросы $S^-$ и $S^+$;
  - ориентированный на вычисление префиксных сумм.
- Подход, ориентированный на запросы $S^-$ и $S^+$:
  - каждая позиция $L_j$ и $R_j$ является критической точкой;
    - на каждой критической точке мы вычисляем префиксную сумму $S$ до этой позиции;
    - для позиции $L_j$ сохраняем значение $S^-(L_j)$, для позиции $R_j$ сохраняем значение $S^+(R_j)$;
  - для вычисления префиксной суммы мы последовательно генерируем элементы массива $A$ до текущей критической точки.
- Подход, ориентированный на префиксных суммах: 
  - каждая позиция $i$ является критической точкой;
    - на каждой критической точке $i$ мы добавляем $A_i$ к префиксной сумме $S$;
  - после обновления префиксной суммы мы обрабатываем все запросы, которые соответствуют текущей позиции $i$.
    - двигаем указатель по массиву сортированных событий.

#### Реализация

##### Подход, ориентированный на запросы

```cpp
auto get_ans = [&]() {
    const int op_prefix_minus = 0, op_prefix_plus = 1; // типы событий

    using event_t = std::tuple<int, int, int>; // {позиция, тип события, индекс запроса}
    std::vector<event_t> events;

    // Собираем события из запросов
    for (size_t j = 0; j < queries.size(); ++j) {
        const auto& [left, right] = queries[j];
        events.emplace_back(left, op_prefix_minus, j); // событие "префикс минус"
        events.emplace_back(right, op_prefix_plus, j); // событие "префикс плюс"
    }

    // Сортируем события по позиции
    std::sort(events.begin(), events.end());

    std::vector<ans_t> answers(queries.size()); // массив ответов на запросы

    ans_t prefix_sum = 0; // текущая префиксная сумма
    
    val_t last_value = 0; // последний вычисленный элемент массива A
    size_t current_index = 0; // текущий индекс в массиве A

    for (const auto& [position, op_type, query_index] : events) {
        // Генерируем элементы массива A до текущей позиции
        while (current_index <= position) {
            ans_t current_value = generate_A(current_index, last_value);
            prefix_sum += current_value;
            current_index += 1;
            
            last_value = current_value;
        }

        // Сохраняем префиксную сумму в ответ на запрос
        if (op_type == op_prefix_minus) {
            answers[query_index] -= prefix_sum;
        } else if (op_type == op_prefix_plus) {
            answers[query_index] += prefix_sum;
        }
    }

    return answers;
}
```

### (Офлайн) Сумма модулей разностей

#### Задача

Даны $N$ функций $f_i(x) = |x - a_i|$ и $Q$ запросов $x_j$.

Для $j$-го запроса найдите сумму значений всех функций в точке $x_j$: $S_j = \sum_{i=1}^{N} |x_j - a_i|$.

#### Решение

- Заметим, что функция $f_i(x) = |x - a_i|$ является кусочно-линейной с "изломом" в точке $a_i$.
  - На отрезке $(-\infty, a_i)$ функция имеет вид $f_i(x) = -x + a_i$.
  - На отрезке $[a_i, +\infty)$ функция имеет вид $f_i(x) = x - a_i$.
- Таким образом, сумма всех функций $S(x) = \sum_{i=1}^{N} f_i(x)$ также является кусочно-линейной с "изломами" в точках $a_i$.
  - На отрезке $(-\infty, a_i)$ функция $S(x)$ имеет вид $S(x) = -N \cdot x + \sum_{i=1}^{N} a_i$.
  - На отрезке $[a_i, +\infty)$ функция $S(x)$ имеет вид $S(x) = N \cdot x - \sum_{i=1}^{N} a_i$.
  - В промежуточной координате $x$ функция $S(x)$ распадается на два слагаемых:
    - $S^-(x) = -k \cdot x + \sum_{a_i < x} a_i$, где $k$ --- количество точек $a_i$, меньших $x$;
    - $S^+(x) = (N - k) \cdot x - \sum_{a_i \ge x} a_i$.
- Таким образом, для вычисления $S(x)$ нам нужно знать:
  - количество точек $a_i$, меньших $x$;
  - сумму точек $a_i$, меньших $x$;
  - сумму точек $a_i$, больших либо равных $x$.
- Все эти величины можно вычислить с помощью подхода с критическими точками:
  - $a_i$ --- критические точки;
  - изначально все $a_i$ включены в сумму "больших либо равных" (так как $x = -\infty$);
  - каждое событие --- перенос точки $a_i$ из "больших либо равных" в "меньшие".
  - параллельно обрабатываем запросы.

#### Реализация

```cpp
auto get_ans = [&]() {
    const int op_move = 0, op_query = 1; // типы событий

    using event_t = std::tuple<int, int, int>; // {координата, тип события, данные события}
    std::vector<event_t> events;

    // Собираем события из точек a_i
    for (size_t i = 0; i < points.size(); ++i) {
        events.emplace_back(points[i], op_move, i); // событие "переноса точки"
    }
    
    // Собираем события из запросов
    for (size_t j = 0; j < queries.size(); ++j) {
        const auto& coord = queries[j];
        events.emplace_back(coord, op_query, j); // событие "запроса"
    }
    
    // Сортируем события по координате
    std::sort(events.begin(), events.end());

    // Отвечаем на запросы
    std::vector<ans_t> answers(queries.size()); 

    int count_less = 0; // количество точек a_i, меньших текущей координаты
    ans_t sum_less = 0; // сумма точек a_i, меньших текущей координаты
    ans_t sum_greater_equal = std::accumulate(points.begin(), points.end(), (ans_t)0); // сумма точек a_i, больших либо равных текущей координате

    for (const auto& [coord, op_type, event_data] : events) {
        if (op_type == op_move) {
            // Перенос точки a_i из "больших либо равных" в "меньшие"
            int point_index = event_data;
            int point_value = points[point_index];
            
            count_less += 1;
            sum_less += point_value;
            sum_greater_equal -= point_value;
        } else if (op_type == op_query) {
            // Ответ на запрос
            int query_index = event_data;
            
            ans_t sum_minus = -count_less * (ans_t)coord + sum_less;
            ans_t sum_plus = (points.size() - count_less) * (ans_t)coord - sum_greater_equal;
            answers[query_index] = sum_minus + sum_plus;
        }
    }

    return answers;
}
```
