# Критические точки

В предыдущих разделах мы рассматривали диапазоны / отрезки на числовой прямой с двумя важными ограничениями:

- все границы / координаты лежали в полуинтервале $[0; M)$;
- сложность по времени / памяти $O(M)$ считалась допустимой.

Но что делать, если эти ограничения не выполняются?

На самом деле нас интересует конкретно ограничение на допустимость сложности $O(M)$, потому что даже реальные задачи будут обладать каким-то заранее известным диапазоном координат $[M^-, M^+]$.

## Уход от обработки всех точек

В общем случае даны $N$ отрезков $[L_i, R_i]$ на числовой прямой, с $i$-м отрезком сопоставлено изменение $d_i$.

Для их обработки:

- в первую очередь мы изменяем значения разностного массива в точках $L_i$ (на $d_i$) и $R_i + 1$ (на $-d_i$) для каждого отрезка;
- затем мы анализируем каждую точку на числовой прямой в порядке возрастания координат, накапливая префикс-сумму обозначенных величин.

В более общем случае информация необязательно будет суммой - мы можем накапливать ответ в какой-то структуре данных.

Без потери общности будем считать, что

- в точке $L_i$ происходит операция $add(d_i)$;
- в точке $R_i + 1$ происходит операция $remove(d_i)$.

### Событийная модель

Обратите внимание - хотя на числовой прямой у нас есть $O(M)$ точек - какие-либо **изменения** нашего состояния происходят только в **конечных** точках отрезков $L_i$ и $R_i + 1$.

Назовём такие точки **критическими**, а сами изменения состояния - **событиями**.

Давайте конкретизируем, что мы знаем про критические точки:

- Всего критических точек не более $2N$ (по две на каждый отрезок), то есть $O(N)$ вместо $O(M)$.
- Между критическими точками состояние **не меняется**.

#### Интервалы стабильности

По сути критические точки разбивают числовую прямую на несколько **интервалов стабильности** - отрезков, на которых состояние не меняется.

Если обозначить критические точки через $c_0 < c_1 < c_2 < \ldots < c_k < c_{k + 1}$, то интервалы стабильности будут выглядеть так:

- $(c_0, c_1)$ со значением $V_0$, где $c_0 = M^-$;
- $[c_1, c_2)$ со значением $V_1$;
- $\ldots$
- $[c_{k-1}, c_k)$ со значением $V_{k-1}$;
- $[c_k, c_{k + 1})$ со значением $V_k$, где $c_{k + 1} = M^+$.

Чаще всего ответ на задачу строится из значений $V_i$:

- либо это сумма, в таком случае она равна $\sum_{i=0}^{k} V_i \cdot (c_{i + 1} - c_i)$;
- либо это экстремум (минимум / максимум), в таком случае он равен $opt(V_0, V_1, \ldots, V_k)$;
- либо ещё какое-то агрегированное значение.

Обратите внимание, что $V_i$ - это необязательно числовое значение, это может быть любое значение / свойство состояния, полученного накоплением уже обработанных событий.

### Принципы обработки критических точек

#### Сортировка событий

Простейший вариант обработки критических точек - честно отсортировать все события и обработать их в порядке возрастания координат.

- Сами события мы знаем из входных данных - это $add(L_i, d_i)$ и $remove(R_i + 1, d_i)$ для каждого отрезка.
- Сортировка всех событий занимает $O(N \log N)$ времени.
- Обработка всех событий занимает $O(N \cdot Op^+ + N \cdot Op^-)$ времени, где $O(Op^+)$ и $O(Op^-)$ - сложность операций $add$ и $remove$ соответственно.

##### События с одинаковой координатой

Обратите внимание, что в случае, если несколько событий имеют одинаковую координату, порядок их обработки может быть важен.

Общего правила здесь нет - всё зависит от конкретной задачи.

В первую очередь это зависит от строгости границ исходных отрезков:

- если отрезки заданы как $[L, R]$ (включительно), то событие $remove$ должно обрабатываться **после** события $add$ в той же точке;
- если отрезки заданы как $[L, R)$ или $(L; R]$ (полуинтервально), то событие $remove$ должно обрабатываться **до** события $add$ в той же точке.

##### (Офлайн) Обработка событий - запросов

В некоторых задачах события могут быть не только изменениями состояния, но и запросами.

В этом случае обычно вводится отдельный тип события, который чаще всего ставится между событиями $add$ и $remove$.

Общая асимптотика в таком случае получается:

- $O((N + Q) \log (N + Q))$ на сортировку всех событий;
- $O(N \cdot Op^+ + N \cdot Op^- + Q \cdot Op^?)$ на обработку всех событий, где $O(Op^?)$ - сложность обработки запроса.

Обратите внимание, что в таком случае запросы обрабатываются в режиме **офлайн** - все запросы известны заранее, а порядок их обработки может отличаться от порядка во входных данных.

##### Пример реализации

```cpp
auto get_ans = [&]() {
    using event_t = std::tuple<int, int, delta_t>; // {координата, тип события, изменение}
    std::vector<event_t> events = {
        { M_plus, op_remove, end_delta } // фиктивное событие в конце
    };

    // Собираем события из отрезков
    for (const auto& [left, right, delta] : segments) {
        events.emplace_back(left, op_add, delta); // событие "начала отрезка"
        events.emplace_back(right + 1, op_remove, delta); // событие "конца отрезка"
    }
    
    // Собираем события из запросов
    for (const auto& [coord, index, _] : queries) {
        events.emplace_back(coord, op_query, index); // событие "запроса"
    }

    // Сортируем события по координате
    std::sort(events.begin(), events.end());
    
    std::vector<ans_t> answers(queries.size()); // массив ответов на запросы

    state_t state = start_state; // объект состояния
    int last_coord = M_minus; // начальная координата

    for (const auto& [coord, op_type, event_data] : events) {
        // Обрабатываем интервал стабильности [last_coord, coord)
        process_stable_interval(last_coord, coord, state);

        // Обновляем состояние в зависимости от типа события
        if (op_type == op_add) {
            state.add(event_data);
        } else if (op_type == op_remove) {
            state.remove(event_data);
        } else if (op_type == op_query) {
            const auto& [_, _, query_type] = queries[event_data];
            answers[event_data] = state.ask(query_type);
        }

        last_coord = coord;
    }

    // возвращаем ответы на запросы
    return answers;
    
    // либо вычисляем один ответ из state
    // return compute_final_answer(state);
}
```
