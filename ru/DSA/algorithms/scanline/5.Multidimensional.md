# Запросы к многомерным диапазонам

## Сканирующая прямая

До этого мы рассматривали запросы к диапазонам в одномерном пространстве.

Обобщением этого подхода на многомерное пространство является использование **сканирующей прямой** (в более общем варианте гиперплоскости).

Важно понимать, что независимо от количества измерений, в подавляющем большинстве ситуаций прямая (или гиперплоскость) будет перемещаться только **вдоль одного измерения** за раз.

Для простоты мы будем называть это измерение "осью $X$".

## Оффлайн-запросы в 2D

В дальнейшем мы будем рассматривать только двумерные случаи - хотя идею и можно обобщить на большее количество измерений, но реализация становится значительно сложнее.

Оси будем обозначать через $X$ (ось, вдоль которой происходят события) и $Y$ (дополнительная перпендикулярная ось).

Чаще всего в таких задачах:

- запросы применяются к прямоугольным областям $(x_1 \le x \le x_2, y_1 \le y \le y_2)$, параллельным осям координат;
- события происходят:
  - либо в точках $(x, y)$,
  - либо вдоль вертикальных отрезков от $(x, y_1)$ до $(x, y_2)$, где $y_1 \le y_2$.

### Схожесть с одномерным случаем

#### События

Все идеи и приёмы, связанные с событийной моделью, сохраняются:

- обработка событий в порядке возрастания координаты $X$;
- поддержание актуального состояния вдоль оси $Y$ с помощью подходящих структур данных;
- обработка запросов при достижении соответствующих координат $X$.

#### Запросы

Схожим остаётся и подход к обработке оффлайн-запросов:

- как в фиксированной координате $X$ (обратите внимание, что вдоль $Y$ запрос может быть диапазонным);
- так и в диапазоне координат $X$ в случае **обратимых** операций.

Случай онлайн-запросов обладает дополнительной сложностью, которую мы рассмотрим в следующем разделе.

### Отличия от одномерного случая

#### Размер пространства состояний

Хотя суммарное количество событий получается аналогичным одномерному случаю $O(N + Q)$, проблема возникает при построении "критической сетки":

- $O(N + Q)$ уникальных координат $X$;
- $O(N + Q)$ уникальных координат $Y$;
- но всего $O((N + Q)^2)$ возможных точек запроса / обновления $(X, Y)$.

Даже если исключить точки запросов из пространства событий, то размер сетки остаётся $O(N^2)$.

Чаще всего это приводит к необходимости построения "неявной" сетки, когда поддерживается только состояние вдоль оси $Y$, актуальное для текущей координаты $X$.

Такой подход сводит потребление памяти к $O(N) + O(N) = O(N)$, но приводит к следующему отличию.

#### Онлайн-запросы вдоль оси $Y$

В памяти хранится только состояние вдоль оси $Y$ для текущей координаты $X$, что приводит к:

- **невозможности** использования **оффлайн**-подходов для $Y$-запросов,
- откуда истекает необходимость использования структур данных, поддерживающих **онлайн-запросы** и **обновления**,
- что чаще всего приводит к необходимости **сжатия координат** вдоль оси $Y$.

#### Онлайн-запросы вдоль оси $X$

Во-первых, подход со сканирующей прямой позволяет обрабатывать только **обратимые** операции при онлайн-запросах.

Во-вторых, вследствие "неявной" сетки, состояние вдоль оси $Y$ необходимо хранить в **персистентной** структуре данных - позволяющей выполнять запросы к каждой своей версии (соответствующей координате $X$).

Случай онлайн-запросов с необратимыми операциями требует специальных структур данных и других подходов, не относящихся к данной теме.

## Применения в задачах

### (Офлайн) Количество точек в прямоугольниках

#### Задача

У вас есть $N$ точек на плоскости и $Q$ запросов. 

Каждый запрос задаёт прямоугольник, параллельный осям координат - требуется найти количество точек, лежащих внутри этого прямоугольника (включая границы).

#### Решение

- Операция "количества" является частным случаем операции "суммы", которая является **обратимой**.

- Назовём префикс-запросом $P(X, y_1, y_2)$ запрос количества точек в прямоугольнике $(x \le X, y_1 \le y \le y_2)$.
  - В таком случае ответ на запрос равен $P(x_2, y_1, y_2) - P(x_1 - 1, y_1, y_2)$.

- Мы будем обрабатывать два вида событий:
  - Добавление точки $(x, y)$: при достижении координаты $X = x$ мы увеличиваем счётчик в позиции $y$ на $1$.
  - Префикс-запрос $P(X, y_1, y_2)$: при достижении координаты $X$ мы вычисляем сумму в диапазоне $[y_1, y_2]$.

- Соответственно, нам нужна структура данных вдоль оси $Y$, поддерживающая операции: 
  - "увеличения в точке";
  - "суммы в диапазоне"
- Примерами таких структур являются:
  - дерево Фенвика (выбор автора),
  - дерево отрезков;
  - корневая декомпозиция и т.д.

#### Реализация

```cpp
auto get_ans = [&]() {
    std::vector<int> critical_xs = get_critical_xs(points, queries);
    std::vector<int> critical_ys = get_critical_ys(points, queries);
    
    // Собираем события
    const int POINT_ADD = 0, QUERY_PLUS = 1, QUERY_MINUS = 2;
    using event_t = std::tuple<int, int, size_t>; // (x, type, index)
    
    std::vector<event_t> events;
    for (size_t pid = 0; pid < points.size(); ++pid) {
        const auto& [x, y] = points[pid];
        int compressed_x = compress_coordinate(x, critical_xs);
        events.emplace_back(compressed_x, POINT_ADD, pid);
    }
    
    for (size_t qid = 0; qid < queries.size(); ++qid) {
        const auto& [x1, y1, x2, y2] = queries[qid];
        int compressed_x1 = compress_coordinate(x1 - 1, critical_xs);
        int compressed_x2 = compress_coordinate(x2, critical_xs);
        events.emplace_back(compressed_x2, QUERY_PLUS, qid);
        events.emplace_back(compressed_x1, QUERY_MINUS, qid);
    }
    
    // Сортируем события по координате X
    std::sort(events.begin(), events.end());
    
    // Отвечаем на запросы
    std::vector<int> answers(queries.size(), 0);
    
    RangeSum range_sum_ds(critical_ys.size()); // Структура данных для суммы в диапазоне вдоль оси Y
    for (const auto& [x, type, index] : events) {
        if (type == POINT_ADD) {
            auto [_, y] = points[index];
            int compressed_y = compress_coordinate(y, critical_ys);
            range_sum_ds.add(compressed_y, 1); // Увеличиваем счётчик в позиции y на 1
        } else {
            const auto& [x1, y1, x2, y2] = queries[index];
            int compressed_y1 = compress_coordinate(y1, critical_ys);
            int compressed_y2 = compress_coordinate(y2, critical_ys);
            int sum_in_range = range_sum_ds.sum(compressed_y1, compressed_y2);
            if (type == QUERY_PLUS) {
                answers[index] += sum_in_range;
            } else {
                answers[index] -= sum_in_range;
            }
        }
    }
    
    return answers;
};
```

### Количество пересекающихся прямоугольников

#### Задача

У вас есть $N$ прямоугольников, параллельных осям координат.

Для каждого прямоугольника требуется найти количество других прямоугольников, пересекающихся с ним.

#### Решение

- Применим подход, аналогичный одномерной задаче - вычислим количество НЕпересекающихся прямоугольников.
  - Два прямоугольника НЕ пересекаются, если один из них находится полностью слева, справа, сверху или снизу от другого.
- Соответственно, мы можем вычислить количество НЕпересекающихся прямоугольников как сумму четырёх величин:
  - количество прямоугольников слева;
  - количество прямоугольников справа;
  - количество прямоугольников сверху;
  - количество прямоугольников снизу.
- Проще всего реализовать вычисление количества прямоугольников строго слева, после чего повернуть плоскость на $90$ градусов три раза, чтобы получить остальные величины.
  - Прямоугольник $j$ находится строго левее $i$, если $x_{2j} < x_{1i}$.
  - Таким образом, достаточно поддерживать один счётчик "количество закончившихся прямоугольников" при обработке событий.
- Проблема такого подхода - мы два раза учитываем прямоугольники, которые находятся "по диагонали" от нас.
  - Для этого необходимо вычислить их количество и вычесть из общего результата.
  - Делать это надо только один раз для каждой диагонали (например, всегда вычитать направление "слева снизу").
  - Либо прибавлять только количество прямоугольников, находящихся "вне" данного направления.
- Для вычисления количества прямоугольников, находящихся "слева снизу", нам всё-таки потребуется использовать структуру данных с операциями:
  - "увеличения в позиции"; 
  - "суммы в диапазоне (префиксе)".
  - Лучше всего для этого подходит дерево Фенвика.

#### Реализация

Привёдем реализацию обработки событий для одного направления - поворот координат вы можете реализовать самостоятельно.

```cpp
auto process_direction = [&]() {
    std::vector<int> critical_xs = get_critical_xs(rectangles);
    std::vector<int> critical_ys = get_critical_ys(rectangles);

    // Собираем события
    const int RECT_START = 0, RECT_END = 1;
    
    // Обратите внимание - прямоугольник начинается раньше, чем заканчивается другой - таким образом мы не учитываем пересечения по границе 

    using event_t = std::tuple<int, int, size_t>; // (x, type, index)

    std::vector<event_t> events;
    for (size_t rid = 0; rid < rectangles.size(); ++rid) {
        const auto& [x1, y1, x2, y2] = rectangles[rid];
        int compressed_x1 = compress_coordinate(x1, critical_xs);
        int compressed_x2 = compress_coordinate(x2, critical_xs);
        events.emplace_back(compressed_x1, RECT_START, rid);
        events.emplace_back(compressed_x2, RECT_END, rid);
    }

    // Сортируем события по координате X
    std::sort(events.begin(), events.end());
    std::vector<int> answers(rectangles.size(), 0);

    RangeSum range_sum_ds(critical_ys.size()); // Структура данных для суммы в диапазоне вдоль оси Y

    int finished_rectangles = 0; // Счётчик "законченных" прямоугольников
    for (const auto& [x, type, index] : events) {
        if (type == RECT_START) {
            answers[index] += finished_rectangles; // Добавляем прямоугольники "слева"
            
            const auto& [x1, y1, x2, y2] = rectangles[index];
            int compressed_y1 = compress_coordinate(y1, critical_ys);
            int count_below = range_sum_ds.sum(0, compressed_y1 - 1);
            
            answers[index] -= count_below; // Вычитаем прямоугольники "слева снизу"
        } else if (type == RECT_END) {
            finished_rectangles += 1;
        }
    }

    return answers;
};
```

### Количество уникальных чисел на отрезке

#### Задача

Дан есть массив $A$ размером $N$ и $Q$ **онлайн**-запросов.

Каждый запрос содержит два целых числа $L$ и $R$ --- вам нужно найти количество **уникальных** чисел в диапазоне $[L, R]$.

#### Решение
