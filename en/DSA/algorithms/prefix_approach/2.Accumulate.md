# Function accumulation

In many problems it's more efficient to process prefixes / suffixes from the empty ones to the whole array:

- $Pref_i = Combine(Pref_{i - 1}, A_i)$.
- $Suff_i = Combine(A_i, Suff_{i + 1})$.

For empty prefixes / suffixes the result is usually known (identity element of the function `Combine`).

In some cases it's possible to replace the array of accumulated results by one variable that stores the current result.

## Functions with constant-memory result

The most basic examples of the accumulating functions are ones whose results can be stored in constant memory.

- minimum (infinity) / maximum (-infinity)
- sum / count (zero)
- greatest common divisor (zero) / least common multiple (one)
- boolean functions: AND (true) / OR (false) / XOR (false)
- etc.

### Duff and Meat

#### Problem

Duff is going to eat meat for $n$ days.

For each day $i$ you know:

- amount of meat $a_i$ Duff wants to eat;
- price per kilogram of meat $p_i$ on that day.

Duff can buy any amount of meat on any day and store it for future days (there is no limit on storage).

Find the minimum total amount of money Duff needs to spend to eat required amount of meat each day.

#### Solution

- to eat meat on day $i$ Duff can buy it on any day $j \le i$;
- to minimize total expenses Duff should always buy meat on the day with the minimum price so far;
- thus we need to accumulate minimum prices for prefixes of the array $p$:
  - $mp_i = \min(mp_{i - 1}, p_i)$;
- then the answer is $\sum_{i = 1}^{n} a_i \cdot mp_i$.

#### Implementation

```cpp
auto get_ans = [&]() {
  int ans = 0;
  
  int inf = 1 + *max_element(p.begin(), p.end());
  
  int min_price = inf;
  for (size_t i = 0; i < n; ++i) {
    min_price = std::min(min_price, p[i]);
    ans += a[i] * min_price;
  }
  
  return ans;
}
```

## Functions with non-constant-memory result

For those functions size of the $Pref_i$ is usually linear to $i$.

Thus, storing all accumulated results requires $O(N^2)$ memory, which is usually not acceptable.

However, in many cases it's possible to optimize memory usage to $O(N)$ by storing result only for the last step and **reusing** it for the next one.

Total time complexity in this case is $O(N \cdot Ins)$, where $Ins$ is the time complexity of inserting one element to the result structure.

Identity element is usually the empty structure.

### Sereja and Suffixes

#### Problem

You have an array $A$ of size $n$ and $q$ queries.

Each query contains integer $k$ ($1 \le k \le n$) - you need to find how many different integers are in the suffix $A_k, A_{k + 1}, \ldots, A_n$.

#### Solution

- It's easy to see that answer for the suffix $k \dots n$ equals to the size of _set_ of the values of this suffix.
  - let's call set for the suffix $k \dots n$ as $S_k$.

- Notice that you can precalculate answers for all suffixes before answering queries. 
  - let's precalculate answers from $n$ down to $1$ - updating the same set on each iteration.

Formally:

- $S_{n + 1} = ()$ (empty set);
- $S_{k} = S_{k + 1} \cup (A_k)$.

#### Implementation

```cpp
auto get_ans = [&]() {
  std::vector<size_t> suffix_uniques(n + 1, 0);

  std::unordered_set<int> suffix_set;
  for (int i = n - 1; i >= 0; --i) {
    suffix_set.insert(a[i]);
    suffix_uniques[i] = suffix_set.size();
  }
  
  std::vector<size_t> answers(q);
  for (int j = 0; j < q; ++j) {
    size_t k = queries[j] - 1;
    answers[j] = suffix_uniques[k];
  }
  
  return answers;
}
```
