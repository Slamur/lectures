# Critical Points

In the previous sections, we considered ranges/segments on the number line with two important constraints:

- all boundaries/coordinates lay within the half-interval $[0; M)$;
- time/memory complexity $O(M)$ was considered acceptable.

But what to do if these constraints are not met?

In fact, we are specifically interested in the constraint on the acceptability of complexity $O(M)$, because even real problems will have some pre-known range of coordinates $[M^-, M^+]$.

## Moving Away from Processing All Points

In general, we are given $N$ segments $[L_i, R_i]$ on the number line, with a change $d_i$ associated with the $i$-th segment.

To process them:

- first, we modify the values of the difference array at points $L_i$ (by $d_i$) and $R_i + 1$ (by $-d_i$) for each segment;
- then we analyze each point on the number line in increasing order of coordinates, accumulating the prefix sum of the designated quantities.

In a more general case, the information does not necessarily have to be a sum - we can accumulate the answer in some data structure.

Without loss of generality, we will assume that

- at point $L_i$, the operation $add(d_i)$ occurs;
- at point $R_i + 1$, the operation $remove(d_i)$ occurs.

### Event Model

Note that although we have $O(M)$ points on the number line, any **changes** to our state occur only at the **finite** points of the segments $L_i$ and $R_i + 1$.

We will call such points **critical**, and the changes in state **events**.

Let's specify what we know about critical points:

- There are at most $2N$ critical points (two for each segment), that is, $O(N)$ instead of $O(M)$.
- Between critical points, the state **does not change**.

#### Stability Intervals

Essentially, critical points divide the number line into several **stability intervals** - segments where the state does not change.

If we denote the critical points as $c_0 < c_1 < c_2 < \ldots < c_k < c_{k + 1}$, then the stability intervals will look like this:

- $(c_0, c_1)$ with value $V_0$, where $c_0 = M^-$;
- $[c_1, c_2)$ with value $V_1$;
- $\ldots$
- $[c_{k-1}, c_k)$ with value $V_{k-1}$;
- $[c_k, c_{k + 1})$ with value $V_k$, where $c_{k + 1} = M^+$.

Most often, the answer to the problem is constructed from the values $V_i$:

- either it is a sum, in which case it equals $\sum_{i=0}^{k} V_i \cdot (c_{i + 1} - c_i)$;
- or it is an extremum (minimum/maximum), in which case it equals $opt(V_0, V_1, \ldots, V_k)$;
- or some other aggregated value.

Note that $V_i$ is not necessarily a numerical value; it can be any value/property of the state obtained by accumulating already processed events.

### Principles of Processing Critical Points

#### Sorting Events

The simplest way to process critical points is to honestly sort all events and process them in order of increasing coordinates.

- We know the events from the input data - these are $add(L_i, d_i)$ and $remove(R_i + 1, d_i)$ for each segment.
- Sorting all events takes $O(N \log N)$ time.
- Processing all events takes $O(N \cdot Op^+ + N \cdot Op^-)$ time, where $O(Op^+)$ and $O(Op^-)$ are the complexities of the $add$ and $remove$ operations, respectively.

##### Events with the Same Coordinate

Note that in the case where several events have the same coordinate, the order of their processing may be important.

There is no general rule here - it all depends on the specific problem.

Primarily, it depends on the strictness of the boundaries of the original segments:

- if the segments are defined as $[L, R]$ (inclusive), then the $remove$ event should be processed **after** the $add$ event at the same point;
- if the segments are defined as $[L, R)$ or $(L; R]$ (half-open), then the $remove$ event should be processed **before** the $add$ event at the same point.

##### (Offline) Processing Events - Queries

In some problems, events can be not only state changes but also queries.

In this case, a separate type of event is usually introduced, which is most often placed between the $add$ and $remove$ events.

The overall asymptotic complexity in this case becomes:

- $O((N + Q) \log (N + Q))$ for sorting all events;
- $O(N \cdot Op^+ + N \cdot Op^- + Q \cdot Op^?)$ for processing all events, where $O(Op^?)$ is the complexity of processing a query.

Note that in this case, queries are processed in **offline** mode - all queries are known in advance, and the order of their processing may differ from the order in the input data.

##### Example Implementation

```cpp
auto get_ans = [&]() {
    using event_t = std::tuple<int, int, delta_t>; // {coordinate, event type, change}
    std::vector<event_t> events = {
        { M_plus, op_remove, end_delta } // dummy event at the end
    };

    // Collect events from segments
    for (const auto& [left, right, delta] : segments) {
        events.emplace_back(left, op_add, delta); // "start of segment" event
        events.emplace_back(right + 1, op_remove, delta); // "end of segment" event
    }
    
    // Collect events from queries
    for (size_t index = 0; index < queries.size(); ++index) {
        const auto& [coord, _] = queries[index];
        events.emplace_back(coord, op_query, index); // "query" event
    }

    // Sort events by coordinate
    std::sort(events.begin(), events.end());
    
    std::vector<ans_t> answers(queries.size()); // array of answers to queries

    state_t state = start_state; // state object
    int last_coord = M_minus; // initial coordinate

    for (const auto& [coord, op_type, event_data] : events) {
        // Process the stability interval [last_coord, coord)
        process_stable_interval(last_coord, coord, state);

        // Update state depending on the type of event
        if (op_type == op_add) {
            state.add(event_data);
        } else if (op_type == op_remove) {
            state.remove(event_data);
        } else if (op_type == op_query) {
            const auto& [_, query_type] = queries[event_data];
            answers[event_data] = state.ask(query_type);
        }

        last_coord = coord;
    }

    // return answers to queries
    return answers;
    
    // or compute a single answer from state
    // return compute_final_answer(state);
}
```

### Coordinate Compression

Instead of directly computing answers "on the fly" while constructing stability intervals, it can sometimes be useful to conveniently split this process into two parts:

- first, we find all critical points, sort them, and assign a new index to each of them - this is called **coordinate compression**;
- then we use these compressed coordinates to answer the existing queries.

The main convenience of this approach lies in the ability to use various data structures that implement certain **range queries** over an array:

- difference array;
- segment tree / Fenwick tree;
- root decomposition;
- etc.

Building such structures can even allow us to switch to answering queries in "online" mode, which can be critical for some problems.

#### Array of Critical Points

First, we need to collect all critical points in sorted order.

Most often, we aim to keep only unique values to minimize the size of the resulting array.

##### Search Tree

```cpp
auto get_critical_points = [&]() {
    search_tree_set<int> critical_points_set;
    
    // Collect critical points from segments
    for (const auto& [left, right, _] : segments) {
        critical_points_set.insert(left);
        critical_points_set.insert(right + 1);
    }
    
    // Collect critical points from queries
    for (const auto& [coord, _] : queries) {
        critical_points_set.insert(coord);
    }
    
    // Move to vector
    std::vector<int> critical_points(critical_points_set.begin(), critical_points_set.end());
    
    return critical_points;
}
```

##### Sorting and Removing Duplicates

```cpp
auto get_critical_points = [&]() {
    std::vector<int> critical_points;

    // Collect critical points from segments 
    for (const auto& [left, right, _] : segments) {
        critical_points.push_back(left);
        critical_points.push_back(right + 1);
    }

    // Collect critical points from queries
    for (const auto& [coord, _] : queries) {
        critical_points.push_back(coord);
    }

    // Sort and remove duplicates
    std::sort(critical_points.begin(), critical_points.end());
    
    // magic C++
    
    // removes all elements in the specified range
    critical_points.erase(
        // moves all unique elements to the front, returns "new end"
        // expects a sorted range 
        std::unique(critical_points.begin(), critical_points.end()),  
        critical_points.end()
    );
    
    /*
    If you are using a language without built-in support for removing duplicates,
    you can do it manually:

    std::vector<int> unique_points;
    for (size_t i = 0; i < critical_points.size(); ++i) {
        if (i == 0 || critical_points[i] != critical_points[i - 1]) {
            unique_points.push_back(critical_points[i]);
        }
    }
    
    */    
    
    return critical_points;
}
```

#### Mapping Compressed Coordinates

Now we need to learn how to map original coordinates to their compressed counterparts.

##### Hash Table

This approach is relevant only if the coordinates of the queries are also known in advance so that they can be compressed.

```cpp
auto build_compression_map = [&](const std::vector<int>& critical_points) {
    hash_table_map<int, int> compression_map;
    
    for (size_t i = 0; i < critical_points.size(); ++i) {
        compression_map[critical_points[i]] = i;
    }
    
    return compression_map;
}

auto compress_coordinate = [&](int coord, const hash_table_map<int, int>& compression_map) {
    return compression_map.get(coord); // return the compressed coordinate
}
```

##### Binary Search

Although this technique has theoretically worse asymptotic complexity $O(\log N)$ per query, in practice it often turns out to be faster due to smaller constants and the absence of overhead from hash tables.

This approach also works even if only the coordinates of the segments are known in advance, but not the queries.

```cpp
auto compress_coordinate = [&](int coord, const std::vector<int>& critical_points) {
    // Find the position of coord in the critical_points array using binary search
    auto it = std::lower_bound(critical_points.begin(), critical_points.end(), coord);
    
    // Return the index of the compressed coordinate
    return std::distance(critical_points.begin(), it);
}
```

## Application in Problems

### Union of Segments

#### Problem

Given $N$ segments $[L_i, R_i]$ on the number line.

Find the union of all segments and output it as the minimum number of non-overlapping segments.

#### Solution

- A new segment from the union starts at each point where the number of covering segments changes from $0$ to $>0$.
- Similarly, a segment from the union ends at each point where the number of covering segments changes from $>0$ to $0$.
- We will maintain the current number of covering segments by processing critical points in order of increasing coordinates.

#### Implementation

```cpp
auto get_ans = [&]() {
    const int op_add = 0, op_remove = 1; // 

    using event_t = std::tuple<int, int>; // {coordinate, event type}
    std::vector<event_t> events;

    // Collect events from segments
    for (const auto& [left, right] : segments) {
        events.emplace_back(left, op_add); // "start of segment" event
        events.emplace_back(right, op_remove); // "end of segment" event
    }

    // Sort events by coordinate
    std::sort(events.begin(), events.end());

    std::vector<segment_t> union_segments; // result - union of segments
    
    int cover_count = 0; // current number of covering segments
    segment_t current_segment; // current union segment

    for (const auto& [coord, op_type] : events) {
        if (op_type == op_add) {
            // Start of a new segment
            if (cover_count == 0) {
                current_segment = segment_t{};
                current_segment.start = coord;
            }
            cover_count += 1;
        } else if (op_type == op_remove) {
            cover_count -= 1;
            // End of the current segment
            if (cover_count == 0) {
                current_segment.end = coord;
                union_segments.push_back(current_segment);
            }
        }
    }

    return union_segments;
}
```

### Number of Covering Segments

#### Problem

Given $N$ segments $[L_i, R_i]$ on the number line and $Q$ queries $x_j$.

For the $j$-th query, find the number of segments that cover the point $x_j$.

Queries need to be processed online.

#### Solution

- We will compress the coordinates of the segment boundaries.
- We will apply a difference array for "range increment" operations.
- To answer each query, we will find the interval that contains the point.
  - The interval search is performed using binary search.

#### Implementation

```cpp
auto get_ans = [&]() {
    std::vector<int> critical_points = get_critical_points();
    
    // Build the difference array
    std::vector<int> cover_count(critical_points.size() + 1, 0);
    for (const auto& [left, right] : segments) {
        int compressed_left = compress_coordinate(left, critical_points);
        int compressed_right = compress_coordinate(right, critical_points);
        
        cover_count[compressed_left] += 1;
        cover_count[compressed_right + 1] -= 1;
    }
    
    // Calculate the number of coverings
    for (size_t i = 1; i < cover_count.size(); ++i) {
        cover_count[i] += cover_count[i - 1];
    }
    
    // Answer the queries
    std::vector<int> answers;
    for (const auto& coord : queries) {
        int compressed_coord = compress_coordinate(coord, critical_points);
        answers.push_back(cover_count[compressed_coord]);
    }
    
    return answers;
}
```

### (Offline) Sum of Absolute Differences

#### Problem

Given $N$ functions $f_i(x) = |x - a_i|$ and $Q$ queries $x_j$.

For the $j$-th query, find the sum of the values of all functions at point $x_j$: $S_j = \sum_{i=1}^{N} |x_j - a_i|$.

#### Solution

- Note that the function $f_i(x) = |x - a_i|$ is piecewise linear with a "kink" at point $a_i$.
  - On the interval $(-\infty, a_i)$, the function is $f_i(x) = -x + a_i$.
  - On the interval $[a_i, +\infty)$, the function is $f_i(x) = x - a_i$.
- Thus, the sum of all functions $S(x) = \sum_{i=1}^{N} f_i(x)$ is also piecewise linear with "kinks" at points $a_i$.
  - On the interval $(-\infty, a_i)$, the function $S(x)$ is $S(x) = -N \cdot x + \sum_{i=1}^{N} a_i$.
  - On the interval $[a_i, +\infty)$, the function $S(x)$ is $S(x) = N \cdot x - \sum_{i=1}^{N} a_i$.
  - In the intermediate coordinate $x$, the function $S(x)$ splits into two terms:
    - $S^-(x) = -k \cdot x + \sum_{a_i < x} a_i$, where $k$ is the number of points $a_i$ less than $x$;
    - $S^+(x) = (N - k) \cdot x - \sum_{a_i \ge x} a_i$.
- Thus, to compute $S(x)$ we need to know:
  - the number of points $a_i$ less than $x$;
  - the sum of points $a_i$ less than $x$;
  - the sum of points $a_i$ greater than or equal to $x$.
- All these quantities can be computed using the critical points approach:
  - $a_i$ are critical points;
  - initially, all $a_i$ are included in the sum of "greater than or equal" (since $x = -\infty$);
  - each event moves point $a_i$ from "greater than or equal" to "less than".
  - Queries are processed in parallel.

#### Implementation

```cpp
auto get_ans = [&]() {
    const int op_move = 0, op_query = 1; // event types

    using event_t = std::tuple<int, int, int>; // {coordinate, event type, event data}
    std::vector<event_t> events;

    // Collect events from points a_i
    for (size_t i = 0; i < points.size(); ++i) {
        events.emplace_back(points[i], op_move, i); // "move point" event
    }
    
    // Collect events from queries
    for (size_t j = 0; j < queries.size(); ++j) {
        const auto& coord = queries[j];
        events.emplace_back(coord, op_query, j); // "query" event
    }
    
    // Sort events by coordinate
    std::sort(events.begin(), events.end());

    // Answer the queries
    std::vector<ans_t> answers(queries.size()); 

    int count_less = 0; // number of points a_i less than the current coordinate
    ans_t sum_less = 0; // sum of points a_i less than the current coordinate
    ans_t sum_greater_equal = std::accumulate(points.begin(), points.end(), (ans_t)0); // sum of points a_i greater than or equal to the current coordinate

    for (const auto& [coord, op_type, event_data] : events) {
        if (op_type == op_move) {
            // Move point a_i from "greater than or equal" to "less than"
            int point_index = event_data;
            int point_value = points[point_index];
            
            count_less += 1;
            sum_less += point_value;
            sum_greater_equal -= point_value;
        } else if (op_type == op_query) {
            // Answer the query
            int query_index = event_data;
            
            ans_t sum_minus = -count_less * (ans_t)coord + sum_less;
            ans_t sum_plus = (points.size() - count_less) * (ans_t)coord - sum_greater_equal;
            answers[query_index] = sum_minus + sum_plus;
        }
    }

    return answers;
}
```
