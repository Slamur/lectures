# Queries on Multidimensional Ranges

## Scanning Line

Previously, we considered queries on ranges in one-dimensional space.

The generalization of this approach to multidimensional space is the use of a **scanning line** (or, in a more general case, a hyperplane).

It is important to understand that regardless of the number of dimensions, in the overwhelming majority of situations, the line (or hyperplane) will move only **along one dimension** at a time.

For simplicity, we will refer to this dimension as the "axis $X$".

## Offline Queries in 2D

From now on, we will only consider two-dimensional cases - although the idea can be generalized to more dimensions, the implementation becomes significantly more complex.

The axes will be denoted as $X$ (the axis along which events occur) and $Y$ (the additional perpendicular axis).

In such problems, queries are most often applied to rectangular areas $(x_1 \le x \le x_2, y_1 \le y \le y_2)$, parallel to the coordinate axes; events occur either at points $(x, y)$ or along vertical segments from $(x, y_1)$ to $(x, y_2)$, where $y_1 \le y_2$.

### Similarity to the One-Dimensional Case

#### Events

All ideas and techniques related to the event model remain:

- Processing events in the order of increasing coordinate $X$;
- Maintaining the current state along the $Y$ axis using appropriate data structures;
- Processing queries upon reaching the corresponding coordinates $X$.

#### Queries

The approach to processing offline queries remains similar:

- Both at a fixed coordinate $X$ (note that along $Y$, the query can be range-based);
- And in the range of coordinates $X$ in the case of **reversible** operations.

The case of online queries has additional complexity, which we will discuss in the next section.

### Differences from the One-Dimensional Case

#### Size of the State Space

Although the total number of events is similar to the one-dimensional case $O(N + Q)$, the problem arises when constructing the "critical grid":

- $O(N + Q)$ unique coordinates $X$;
- $O(N + Q)$ unique coordinates $Y$;
- But a total of $O((N + Q)^2)$ possible query/update points $(X, Y)$.

Even if we exclude query points from the event space, the size of the grid remains $O(N^2)$.

This often leads to the necessity of constructing an "implicit" grid, where only the state along the $Y$ axis, relevant to the current coordinate $X$, is maintained.

This approach reduces memory consumption to $O(N) + O(N) = O(N)$, but leads to the following distinction.

#### Online Queries Along the $Y$ Axis

Only the state along the $Y$ axis for the current coordinate $X$ is stored in memory, which leads to:

- **The impossibility** of using **offline** approaches for $Y$-queries,
- From which arises the necessity to use data structures that support **online queries** and **updates**,
- Which often leads to the necessity of **coordinate compression** along the $Y$ axis.

#### Online Queries Along the $X$ Axis

Firstly, the scanning line approach allows processing only **reversible** operations in online queries.

Secondly, due to the "implicit" grid, the state along the $Y$ axis must be stored in a **persistent** data structure - allowing queries to each of its versions (corresponding to the coordinate $X$).

The case of online queries with irreversible operations requires special data structures and other approaches not related to this topic.

## Applications in Problems

### Number of Points in Rectangles

#### Problem

You have $N$ points on a plane and $Q$ queries.

Each query defines a rectangle parallel to the coordinate axes - you need to find the number of points lying inside this rectangle (including the boundaries).

#### Solution

- The "count" operation is a special case of the "sum" operation, which is **reversible**.

- We will call the prefix query $P(X, y_1, y_2)$ the query for the number of points in the rectangle $(x \le X, y_1 \le y \le y_2)$.
  - In this case, the answer to the query is $P(x_2, y_1, y_2) - P(x_1 - 1, y_1, y_2)$.

- We will process two types of events:
  - Adding a point $(x, y)$: upon reaching the coordinate $X = x$, we increase the counter at position $y$ by $1$.
  - Prefix query $P(X, y_1, y_2)$: upon reaching coordinate $X$, we compute the sum in the range $[y_1, y_2]$.

- Accordingly, we need a data structure along the $Y$ axis that supports operations:
  - "increase at a point";
  - "sum in a range".
- Examples of such structures include:
  - Fenwick tree (author's choice),
  - Segment tree;
  - Root decomposition, etc.

#### Implementation

```cpp
auto get_ans = [&]() {
    std::vector<int> critical_xs = get_critical_xs(points, queries);
    std::vector<int> critical_ys = get_critical_ys(points, queries);
    
    // Collecting events
    const int POINT_ADD = 0, QUERY_PLUS = 1, QUERY_MINUS = 2;
    using event_t = std::tuple<int, int, size_t>; // (x, type, index)
    
    std::vector<event_t> events;
    for (size_t pid = 0; pid < points.size(); ++pid) {
        const auto& [x, y] = points[pid];
        int compressed_x = compress_coordinate(x, critical_xs);
        events.emplace_back(compressed_x, POINT_ADD, pid);
    }
    
    for (size_t qid = 0; qid < queries.size(); ++qid) {
        const auto& [x1, y1, x2, y2] = queries[qid];
        int compressed_x1 = compress_coordinate(x1 - 1, critical_xs);
        int compressed_x2 = compress_coordinate(x2, critical_xs);
        events.emplace_back(compressed_x2, QUERY_PLUS, qid);
        events.emplace_back(compressed_x1, QUERY_MINUS, qid);
    }
    
    // Sorting events by coordinate X
    std::sort(events.begin(), events.end());
    
    // Answering queries
    std::vector<int> answers(queries.size(), 0);
    
    RangeSum range_sum_ds(critical_ys.size()); // Data structure for range sum along the Y axis
    for (const auto& [x, type, index] : events) {
        if (type == POINT_ADD) {
            auto [_, y] = points[index];
            int compressed_y = compress_coordinate(y, critical_ys);
            range_sum_ds.add(compressed_y, 1); // Increase the counter at position y by 1
        } else {
            const auto& [x1, y1, x2, y2] = queries[index];
            int compressed_y1 = compress_coordinate(y1, critical_ys);
            int compressed_y2 = compress_coordinate(y2, critical_ys);
            int sum_in_range = range_sum_ds.sum(compressed_y1, compressed_y2);
            if (type == QUERY_PLUS) {
                answers[index] += sum_in_range;
            } else {
                answers[index] -= sum_in_range;
            }
        }
    }
    
    return answers;
};
```

### Number of Intersecting Rectangles

#### Problem

You have $N$ rectangles parallel to the coordinate axes.

For each rectangle, you need to find the number of other rectangles that intersect with it.

#### Solution

- We will apply an approach similar to the one-dimensional problem - we will compute the number of NON-intersecting rectangles.
  - Two rectangles do NOT intersect if one is completely to the left, right, above, or below the other.
- Accordingly, we can compute the number of NON-intersecting rectangles as the sum of four quantities:
  - the number of rectangles to the left;
  - the number of rectangles to the right;
  - the number of rectangles above;
  - the number of rectangles below.
- It is easiest to implement the calculation of the number of rectangles strictly to the left, after which we can rotate the plane 90 degrees three times to obtain the other quantities.
  - Rectangle $j$ is strictly to the left of $i$ if $x_{2j} < x_{1i}$.
  - Thus, it is sufficient to maintain one counter for the "number of finished rectangles" while processing events.
- The problem with this approach is that we count rectangles that are "diagonally" from us twice.
  - To address this, we need to compute their number and subtract it from the total result.
  - This should be done only once for each diagonal (for example, always subtracting in the "bottom left" direction).
  - Or we can add only the number of rectangles that are "outside" this direction.
- To compute the number of rectangles that are "below left", we will still need to use a data structure with operations:
  - "increase at position"; 
  - "sum in range (prefix)".
  - A Fenwick tree is best suited for this.

#### Implementation

Here is the implementation for processing events in one direction - you can implement the coordinate rotation yourself.

```cpp
auto process_direction = [&]() {
    std::vector<int> critical_xs = get_critical_xs(rectangles);
    std::vector<int> critical_ys = get_critical_ys(rectangles);

    // Collecting events
    const int RECT_START = 0, RECT_END = 1;
    
    // Note - a rectangle starts before another ends - thus we do not count intersections on the boundary 

    using event_t = std::tuple<int, int, size_t>; // (x, type, index)

    std::vector<event_t> events;
    for (size_t rid = 0; rid < rectangles.size(); ++rid) {
        const auto& [x1, y1, x2, y2] = rectangles[rid];
        int compressed_x1 = compress_coordinate(x1, critical_xs);
        int compressed_x2 = compress_coordinate(x2, critical_xs);
        events.emplace_back(compressed_x1, RECT_START, rid);
        events.emplace_back(compressed_x2, RECT_END, rid);
    }

    // Sorting events by coordinate X
    std::sort(events.begin(), events.end());
    std::vector<int> answers(rectangles.size(), 0);

    RangeSum range_sum_ds(critical_ys.size()); // Data structure for range sum along the Y axis

    int finished_rectangles = 0; // Counter for "finished" rectangles
    for (const auto& [x, type, index] : events) {
        if (type == RECT_START) {
            answers[index] += finished_rectangles; // Adding rectangles "to the left"
            
            const auto& [x1, y1, x2, y2] = rectangles[index];
            int compressed_y1 = compress_coordinate(y1, critical_ys);
            int count_below = range_sum_ds.sum(0, compressed_y1 - 1);
            
            answers[index] -= count_below; // Subtracting rectangles "below left"
        } else if (type == RECT_END) {
            finished_rectangles += 1;
        }
    }

    return answers;
};
```

### Number of Unique Numbers in a Segment

#### Problem

Given an array $A$ of size $N$ and $Q$ **online** queries.

Each query contains two integers $L$ and $R$ - you need to find the number of **unique** numbers in the range $[L, R]$.

#### Solution

- Initially, it may seem that this problem has no relation to the scanning line.
  - Although the "count in a segment" operation is reversible, it is unclear how to combine it with the uniqueness of numbers.
- Let's try to reformulate the problem:
  - We need to find the number of positions $i$ in the segment $[L, R]$ such that $A_i$ appears in the range $[L, R]$ **for the first time**.
  - Essentially, we ignore all such positions $j$ where $A_j = A_i$, with $L \le i < j \le R$.
- But how do we know that position $i$ is the first for the number $A_i$ in the segment $[L, R]$?
  - Let $prev_i$ be the position of the **previous** occurrence of the number $A_i$ in the array (or $0$ if there is none).
  - In this case, position $i$ is the first in the segment $[L, R]$ if $prev_i < L \le i \le R$.
- We can map positions $i$ to the point $(x = i, y = prev_i)$ on the plane.
  - Then the condition $prev_i < L \le i \le R$ can be rewritten as $(x = i, y = prev_i)$ lying in the rectangle $(L \le x \le R, y < L)$.
  - Thus, each query turns into a familiar query for the number of points in a rectangle.
- I should clarify that this solution can also be reformulated in a more "event-driven" manner:
  - We will maintain a set of "active" positions that need to be considered when answering the query.
  - Upon reaching position $i$, we add it to the set while simultaneously removing position $prev_i$, if it exists.
    - Essentially, each "active" position corresponds to the last occurrence of a number among already processed positions.
  - Thus, each query will occur at position $R$ and request the number of "active" positions in the range $[L, R]$.
- Regardless of the chosen approach, we need a **persistent** data structure (due to the online nature of the queries) that supports operations:
  - adding at a position;
  - summing in a range.
- A classic example of such a structure is a persistent segment tree.
  - The overall time complexity in this case is $O(N \log N + Q \log N)$.
  - The memory complexity will be $O(N \log N)$ to store all versions of the tree.

#### Implementation

```cpp
auto get_ans = [&]() {
    std::vector<int> critical_ys = get_critical_ys(a);

    // Building a persistent segment tree
    // All versioning logic is encapsulated within
    PersistentRangeSum persistent_range_sum_ds(critical_ys.size());

    // Scanning the array and building versions
    std::unordered_map<int, int> last_occurrence; // Storing the last occurrence of a number
    
    std::vector<int> query_versions(a.size() + 1); // Versions of the data structure relevant for queries
    query_versions[0] = persistent_range_sum_ds.get_initial_version(); // Empty version
    
    for (size_t i = 0; i < a.size(); ++i) {
        int prev_index = -1;
        
        auto last_it = last_occurrence.find(a[i]);
        if (last_it != last_occurrence.end()) {
            prev_index = last_it->second;
        }
        last_occurrence[a[i]] = i;

        query_versions[i + 1] = persistent_range_sum_ds.update_last(i, 1); // Adding the current occurrence

        if (prev_index != -1) {
            query_versions[i + 1] = persistent_range_sum_ds.update_last(prev_index, -1); // Removing the previous occurrence
        }
    }

    // Answering queries
    std::vector<int> answers;

    for (const auto& [left, right] : queries) {
        int version_r = query_versions[right];
        
        int ans = persistent_range_sum_ds.sum_in_range(version_r, left, right);
        answers.push_back(ans);
    }
    
    return answers;
}
```

### Area of Union of Rectangles

#### Problem

You have $N$ rectangles parallel to the coordinate axes.

You need to find the area of the union of all these rectangles.

#### Solution

- We will scan the plane along the $X$ axis.
  - The critical coordinates will be the coordinates $x$ of the start and end of the rectangles.
- We will call a rectangle "active" if the current coordinate $X$ lies within its projection on the $X$ axis.
  - Between any two critical coordinates $X$, the set of active rectangles remains unchanged.
  - Accordingly, the projection of the union of active rectangles on the $Y$ axis also remains unchanged.
- The total area of the union of rectangles is the sum of the areas of "horizontal strips" between critical coordinates $X$.
  - We know the width of the strip (along the $X$ axis) - this is the difference between the current and previous critical coordinate $X$.
  - We still need to compute the total height of the strips in this interval of stability.
- Consider the following event model:
  - At the left boundary of a rectangle, we add its vertical segment to the current state.
  - At the right boundary of a rectangle, we remove its vertical segment from the current state.
- We need a data structure that supports operations:
  - Adding in a range (vertical segment);
  - Summing weights corresponding to non-zero values across the entire array (coverage).
    - In this case, the weights are the lengths of segments between critical coordinates $Y$. 
- The first operation can be easily performed using a segment tree with lazy updates.
  - But this does not efficiently combine with counting the sum of non-zero values.
- We will go in reverse - compute the sum of weights for zero values in the array, and then subtract it from the total sum.
- But how to maintain the count of specific values during lazy addition operations in the range?
  - The nature of the algorithm is such that the value $0$ is the minimum possible at any time.
  - Accordingly, we can reformulate the query as a query for "sum over minimum values," provided that the minimum equals $0$.
  - During lazy addition over the entire range, only the minimum value itself changes, but not the corresponding sum of weights.

#### Implementation

```cpp
auto get_ans = [&]() {
    std::vector<int> critical_xs = get_critical_xs(rectangles);
    std::vector<int> critical_ys = get_critical_ys(rectangles);

    // Collecting events
    const int RECT_START = 0, RECT_END = 1; 

    using event_t = std::tuple<int, int, size_t>; // (x, type, index)
    std::vector<event_t> events;

    for (size_t rid = 0; rid < rectangles.size(); ++rid) {
        const auto& [x1, y1, x2, y2] = rectangles[rid];
        int compressed_x1 = compress_coordinate(x1, critical_xs);
        int compressed_x2 = compress_coordinate(x2, critical_xs);
        events.emplace_back(compressed_x1, RECT_START, rid);
        events.emplace_back(compressed_x2, RECT_END, rid);
    }

    // Sorting events by coordinate X
    std::sort(events.begin(), events.end());

    // Precomputing weights for segments between critical coordinates Y
    std::vector<int> y_segment_lengths;
    for (size_t i = 1; i < critical_ys.size(); ++i) {
        int weight = critical_ys[i] - critical_ys[i - 1];
        y_segment_lengths.push_back(weight);
    }
    
    int total_y_length = critical_ys.back() - critical_ys.front();

    // Data structure for sum over minimum values along the Y axis
    RangeSumOverMin range_sum_over_min_ds(y_segment_lengths);

    int prev_x = critical_xs[0];
    ans_t total_area = 0;

    for (const auto& [x, type, index] : events) {
        int current_x = critical_xs[x];
        int delta_x = current_x - prev_x;

        // minimum and sum over corresponding positions
        const auto [min_value, min_pos_sum] = range_sum_over_min_ds.get_sum_over_min();
         
        int covered_y_length = (min_value > 0) ? 0 : (total_y_length - min_pos_sum);
        total_area += (ans_t)delta_x * covered_y_length;

        const auto& [x1, y1, x2, y2] = rectangles[index];
        int compressed_y1 = compress_coordinate(y1, critical_ys);
        
        // each Y coordinate corresponds to a segment between it and the next critical Y coordinate
        // therefore we ignore the last coordinate, as we add "up to it" inclusively
        int compressed_y2 = compress_coordinate(y2, critical_ys) - 1;
        
        int rect_delta = (type == RECT_START) ? 1 : -1;
        range_sum_over_min_ds.add_in_range(compressed_y1, compressed_y2, rect_delta); // Adding vertical segment

        prev_x = current_x;
    }

    return total_area;
};
```
